# Portfolio coverage extension v3 — 2026-11-21

This protocol is written before selecting or evaluating the new cohort. It follows inspection of the original five-product final and exploratory results, so it is a retrospective exploratory generalisation check, not preregistered independent confirmation. The original final result/receipt and v2 study must remain unchanged. Existing forecast methods/hyperparameters are frozen; no favourable model result is required.

Source: the already-downloaded original UCI Online Retail II workbook. Canonical validation/quarantine rules are unchanged. Original customer fields remain local and are dropped from all published canonical records. Record original workbook/archive hashes, input/retained/quarantined counts and quarantine reasons. The original five research SKUs are excluded from this cohort.

Eligibility and sampling use only the first sixty calendar days of the original source: positive sales, first sale within fourteen days, at least two positive-sale days. Build six strata: first-sixty-day volume tercile (low/middle/high, stable SKU tie-breaking), crossed with sparse versus dense recorded sales (>50% versus <=50% zero days on the shared sixty-day calendar). These are descriptive operational segments under the explicit zero-recorded-sales coverage assumption, not latent-demand classes. Within each stratum, rank SHA-256(seed 20261121 + SKU), and take up to eight products. Maximum cohort48; underfilled strata must be reported and never silently filled from other segments. Retain all selected products regardless of later performance. Selection metadata is published before evaluation.

Forecast evaluation: same five fixed methods and thirteen non-overlapping seven-day origins as v2 (L-98 through L-14; L=max transaction date minus one). All targets end by L-7; never access the original final target window. Train only through each origin. Unknown/short-history failures remain visible. Report global, segment and product WAPE with actual denominators, MAE and signed bias. Also compute seasonal MASE using the mean absolute seven-day difference in training history only; a zero scaling denominator means undefined MASE. Report valid/undefined product-fold counts explicitly. Method failure or unequal cohort coverage blocks paired inference.

Compare each method to weekday mean through the existing synchronized two-week circular block resampling (2,000 replicates, seed20261121). Weekly blocks contain the complete selected cross-section, preserving within-week/product dependence. Thirteen blocks, the one-retailer source, retrospective design, artificial circular boundaries and unadjusted comparisons limit inference. Do not claim population superiority, causal savings or demand-censoring correction. Keep both product wins and losses, and segment reversals. This study does not change the operational purchasing model or the previous policy comparisons.

Engineering acceptance: attempt an isolated Python virtual-environment installation from the locked dependencies; actually run tests, lint, compilation and the browser workflow there where supported. Preserve failed installation logs instead of presenting an inherited environment as clean. Add a single verification entry point producing a versioned machine-readable report with actual command outcomes, versions, hashes and UTC timestamps. No external deployment, customer feedback or live purchasing is inferred from these checks.
